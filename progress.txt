[Day 4 - 2026-09-25]
--------------------------------------------------------------------------------
1. Reverse Engineering & Binary Analysis (Ghidra & Binary Structures)
   - Studied binary compilation pipelines, symbol tables, and debug metadata in executable formats (ELF / PE).
   - Core concepts & practical differences:
     * Stripped vs. Non-Stripped binaries:
       - Non-stripped binaries retain symbol tables (`.symtab`), string tables (`.strtab`), and debugging information (DWARF/PDB), preserving human-readable function/variable names.
       - Stripped binaries have `.symtab` and debug symbols removed to reduce binary footprint and hinder reverse engineering.
       - Dynamic symbols (`.dynsym`, PLT/GOT) remain in stripped binaries to allow dynamic linking with shared libraries (e.g., `libc`).
     * Identified binary states using CLI utilities: `file <binary>`, `nm`, `readelf -s`, and `objdump`.
   - Reverse engineering workflows in Ghidra:
     * Analyzing non-stripped binaries with full symbol tree visibility, function names, and accurate decompilation.
     * Navigating stripped binaries where functions default to address-based placeholders (`FUN_<address>`).
     * Tracing execution flow from entry point (`_start`) through `__libc_start_main` to locate `main()`.
     * Using string cross-references (`Defined Strings` / `XREFs`) and external library call patterns (`.dynsym`) to reconstruct function logic.
     * Renaming symbols (`L`) and re-typing variables (`Y`) to progressively document decompiled pseudocode.

--------------------------------------------------------------------------------
Key Takeaways & Reflection:
- Stripping removes convenience (function names, local variable names), but does not remove code logic or dynamic library imports.
- In stripped binaries, strings and external API calls serve as the primary anchors for locating the main logic and understanding program behavior.
